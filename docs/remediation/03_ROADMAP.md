# Roamio 整改路线图

更新时间：2026-05-04

## 路线总览

整改分为四条线并行推进，但代码修改按阶段串行落地：

1. 安全线：密钥、配置、公开仓库风险。
2. 可运行线：本地启动、依赖、数据库、缓存、构建。
3. 架构线：后端边界、前端 API、旧接口冻结。
4. 验证线：smoke test、核心流程测试、部署检查。

## Milestone 1：安全止血

目标时间：第 1 周

任务：
- 确认仓库中所有疑似敏感信息。
- 轮换 Qwen/DashScope（历史）、DeepSeek（当前）、QQ、COS、数据库、邮箱、Django `SECRET_KEY` 等凭据。
- 脱敏文档。
- 移除代码里的默认真实密钥。
- 明确 `roamio-master/` 处理方式。

验收标准：
- 敏感关键词扫描无真实凭据。
- `.env.example` 只保留占位符。
- 文档不再包含真实服务器凭据。

## Milestone 2：本地可运行

目标时间：第 1-2 周

任务：
- 拆分 dev/prod settings。
- 确认本地数据库方案，优先支持 SQLite 或本地 MySQL 二选一。
- 确认 Redis 不可用时的本地降级方案。
- 后端可以 `manage.py check`。
- 前端可以安装依赖并构建。

验收标准：
- README 或开发文档中有明确启动步骤。
- 后端和前端可在本地启动。
- 不依赖生产服务即可跑基础流程。

## Milestone 3：最小测试网

目标时间：第 2 周

任务：
- 增加后端 smoke tests。
- 覆盖 Trip CRUD、权限、评论、AI 输出清洗。
- 增加前端构建检查。
- 整理手测清单。

验收标准：
- 每次整改前后能跑同一组检查。
- 核心路径失败时能尽早发现。

## Milestone 4：后端边界整理

目标时间：第 3-4 周

任务：
- 生成当前 API 路由清单。
- 标记旧接口、新接口、废弃接口。
- 先按目录整理领域边界。
- 清理重复 utility，例如 email、COS、QQ OAuth、Ralendar client 的多处拷贝。
- 明确 `Trip`、`SiteStat`、`Comment.page` 兼容策略。

验收标准：
- 新功能有明确放置位置。
- 旧接口冻结，不再继续扩展。
- 工具模块没有明显重复实现。

## Milestone 5：核心链路重构

目标时间：第 2 个月

任务：
- 重构认证链路。
- 重构 Trip 编辑和发布链路。
- 重构 AI 生成保存链路。
- 重构 Trip 详情和评论链路。
- 整理 Ralendar 同步链路。

验收标准：
- 每条链路有测试或手测步骤。
- 前端关键页面能完整走通。
- API 响应结构稳定。

## Milestone 6：部署整理

目标时间：第 2 个月

任务：
- 更新生产部署文档。
- 确认是否继续提交 `web/dist/`。
- 明确静态资源、媒体资源、COS、CDN 的边界。
- 建立备份和恢复流程。

验收标准：
- 部署流程可重复。
- 回滚路径明确。
- 生产配置不依赖本地开发假设。

## 建议第一批实际修改

1. 处理 `roamio-master/`。
2. 脱敏文档和配置默认值。
3. 拆分 settings。
4. 补最小后端检查。
5. 确认 AI 本地修改是否保留。

## 暂不建议做的事

- 暂不整体重写后端。
- 暂不一次性拆多个 Django app。
- 暂不移除 `web/dist/`，除非已经确认部署链路不依赖它。
- 暂不继续扩展 AI/Ralendar/支付功能，直到核心链路可验证。
