# Roamio 整改方案

更新时间：2026-05-04

## 整改目标

1. 恢复项目可维护性：新开发者能在本地启动、理解主要模块、跑基本验证。
2. 降低安全风险：移除仓库中的敏感信息，轮换已暴露密钥。
3. 明确架构边界：让认证、旅行、评论、AI、Ralendar、存储等职责各归其位。
4. 建立验证闭环：每次修改都能通过最小测试或检查证明没有破坏核心流程。
5. 为后续产品迭代打基础：先整理主线，再继续做功能。

## 整改原则

- 不立即重写整个项目。
- 不在未建立测试和启动链路前做大规模搬迁。
- 不同时修改多个业务域。
- 兼容旧接口，但停止扩展旧接口。
- 每个阶段都要产出可验收结果。

## 阶段 0：冻结和盘点

目标：
- 明确当前代码、文档、环境和部署真实状态。

步骤：
1. 记录当前 Git 状态和未提交改动。
2. 确认 `roamio-master/` 是否为残留目录。
3. 列出所有路由、前端页面、API 调用和外部服务。
4. 标记可信文档、历史文档、过期文档。

验收：
- 有一份当前状态说明。
- 不再把重复目录纳入代码搜索和维护范围。

## 阶段 1：安全和配置止血

目标：
- 把最危险的问题先处理掉。

步骤：
1. 搜索并脱敏仓库中的密钥、密码、服务器地址。
2. 轮换所有出现过的真实凭据。
3. 拆分 Django settings：
   - `base`：通用配置
   - `dev`：本地开发
   - `prod`：生产部署
4. 移除代码中的默认真实密钥。
5. 更新 `.env.example`。
6. 增加基础密钥扫描脚本或 pre-commit 说明。

验收：
- `rg` 搜索不到真实密钥。
- 本地可用 dev 配置启动。
- 生产配置不允许默认 `DEBUG=True`。

## 阶段 2：恢复本地运行和最小验证

目标：
- 让项目可以被稳定启动和验证。

步骤：
1. 确认 Python 依赖，补齐 MySQL/SQLite 开发说明。
2. 确认 Node 依赖和前端构建。
3. 建立最小 smoke test：
   - Django import/check
   - migration check
   - Trip 创建/读取
   - 公开/私有权限
   - AI JSON 清洗
4. 写本地启动文档。

验收：
- 新环境按文档可以启动后端和前端。
- 最小测试可以稳定通过。

## 阶段 3：后端边界整理

目标：
- 降低后端模块混乱度。

步骤：
1. 绘制当前 API 路由表。
2. 标记旧接口和新接口：
   - 新功能只进入 `/api/v1/`
   - 旧 `backend.views` 只做兼容
3. 先按目录重组：
   - `accounts`
   - `trips`
   - `comments`
   - `ai`
   - `integrations/ralendar`
   - `storage`
   - `billing`
4. 对 `Trip`、`SiteStat`、`Comment.page` 的历史兼容关系做专项清理方案。

验收：
- 每个业务模块有明确入口和负责人文件。
- 旧接口冻结清单明确。

## 阶段 4：核心业务链路重构

目标：
- 优先整理最常用、最容易坏的链路。

优先链路：
1. 用户注册/登录/当前用户信息。
2. Trip CRUD 和权限控制。
3. AI 生成 -> 清洗 -> 应用到 Trip。
4. Trip 详情展示和评论互动。
5. Ralendar 账号绑定与同步。

做法：
- 每次只处理一条链路。
- 先补测试，再改实现。
- 保留 API 响应兼容，必要时增加版本化字段。

验收：
- 核心链路有测试或手测脚本。
- 前端页面能走通主要流程。

## 阶段 5：前端整理

目标：
- 让前端调用、认证、错误处理和页面结构更清晰。

步骤：
1. 统一 API 响应处理。
2. 把认证状态和 token 刷新策略从请求层中理清。
3. 梳理页面路由，隔离临时活动页。
4. 逐步拆分过大的 Vue 组件。
5. 明确是否继续提交 `web/dist/`。

验收：
- 认证错误、普通接口错误、上传错误有一致处理方式。
- 页面路由清晰，临时活动不污染主业务。

## 阶段 6：部署和运维整理

目标：
- 让部署可重复、可回滚。

步骤：
1. 确认当前服务器部署方式。
2. 更新 Nginx/uWSGI 配置说明。
3. 明确静态资源和媒体资源策略。
4. 建立备份和恢复流程。
5. 后续考虑 CI/CD。

验收：
- 有一份可执行部署文档。
- 服务重启、迁移、回滚流程明确。
